# Упрощение отчёта сверки

Решение пользователя от 16.10.2026: убрать лишнюю диагностику из рабочего отчёта,
сохранить код для возможного возврата и зафиксировать изменения в Git.

## Архив

Полная расширенная реализация и её тесты сохранены коммитом `734b357` в ветке
`archive/reconciliation-diagnostics-20261016`. До изменений проходят 297 тестов
на Python 3.11. Рабочая ветка упрощения — `fix/compact-reconciliation-report`.
Архивный коммит не означает пригодность этой версии к промышленному выпуску.
Реальные JSON, XLSX и `.env` в архив не включены.

Для чтения прежнего кода: `git show 734b357:app/reconciliation.py`.
Для пробного запуска прежней версии — отдельный checkout архивной ветки.
Не восстанавливать архив целиком поверх рабочей версии: он содержит поведение,
из-за которого возникли тысячи ручных строк.

## Граница упрощения

Сохраняются новые поля 1С, сопоставление реализации по выданному счёту-фактуре,
импорта по партии и контрагенту, количества внутри найденной пары, знак БУХ − УТ,
соответствия складов, реальные начальные/конечные расхождения и разделение организаций.
Количество товара не выбирает пару документов.

1. Вернуть путь сопоставления по единственному явному исходному идентификатору.
2. Не создавать отдельные товарные рекомендации из отсутствующей контрольной точки.
3. Области с непроверенными остатками и отсутствующим соответствием склада
   кратко показывать в «Итогах», без массовых строк на листе документов.
   Неизвестное значение не становится нулём и не считается успешной сверкой.
4. Один ручной документный случай занимает одну строку в рамках тех же складов,
   организаций и кандидатов. Товарные подробности, исходные количества и остатки
   сохраняются согласованными строками внутри ячеек, без суммирования.
5. Пустое необязательное описание единицы не блокирует сравнение переданных
   количеств. Явное различие известных единиц/упаковок остаётся ручным случаем.
6. Сохранить доказанные исправления потери данных и защиту от двойного учёта.

## Проверка

Для новых правил сначала добавляются падающие тесты JSON → расчёт → XLSX.
Проверяются разделение случаев по складам/организациям/кандидатам, восстановление
всех товарных подробностей из компактной строки, отсутствие выдуманного нуля,
историческая пара 537/550/+13 и отсутствие ошибки у равной пары 550/550.
Полный набор выполняется на Python 3.11 и 3.12. Свежие июльские ответы используются
повторно в памяти; коммерческие JSON не сохраняются.
